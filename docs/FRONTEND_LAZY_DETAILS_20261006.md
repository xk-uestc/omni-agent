# 前端折叠详情延迟生成

用户反馈8030首页前端慢。本轮先区分页面加载、工具结果渲染和模型等待；未调用付费模型API。

本地HTTP读取首页5.4ms、health21.1ms、schema2.8ms、app.js15.8ms。Edge首页首次导航DOM就绪160.7ms、load242.5ms。单次观测不是稳定加载基准，也不代表用户已有多轮聊天状态。

确认的渲染问题：工具详情处于关闭状态时仍执行完整JSON序列化、16000字符语法分词和React节点生成；每次其他工具更新又重复渲染已有条目。数据库字段SVG和查询详情也在答案返回时提前生成。

修复：Code与Tool使用React.memo，详情通过原生details的toggle按打开状态生成Code；附件作为明确属性参与memo更新，避免后加附件被忽略。SQL输入/反馈切换和复制保留。完整数据库SVG及查询依据在首次展开时生成。附件节点保持绑定以保留已有事件及展开状态。脚本资源版本更新使用户刷新后加载新代码。

同一合成场景，25条较大工具反馈、每条1500个带长描述条目：

| 指标 | 修复前 | 修复后 |
|---|---:|---:|
| 等待两帧后的渲染耗时 | 419.8ms | 12.8ms |
| DOM节点 | 20352 | 627 |
| 关闭详情中的代码块 | 25 | 0 |
| 关闭时序列化/高亮次数 | 25/25 | 0/0 |

展开后代码块和反馈内容均存在。各版本一次运行，不能称整体网页提速33倍；首页修复后导航337ms，初次加载并没有改善证据。前后原始报告FRONTEND_LATENCY_BEFORE_20261006.json及FRONTEND_LATENCY_AFTER_20261006.json。

前端27项测试通过。真实HTTP/Edge浏览器21项通过，包含关闭时不生成代码和字段SVG、打开后SQL高亮、字段图、切换标签、原文答案反馈、移动端及无运行异常。旧同步检查在点击后立即检查节点不适合延迟生成，首次运行4项失败保留于runtime；改为等待目标节点可见，保持原检查内容，终版全部通过。终版报告FRONTEND_LAZY_BROWSER_20261006.json。

从既有终版36题审计读取，每题模型请求累计耗时中位33.5秒、最高254.1秒。这是串行请求耗时累加而非准确用户墙钟时间；它说明等待文档答案仍主要需要后端模型调用链优化。本轮未降低来源/条件复核，不宣称答案生成速度提升。
