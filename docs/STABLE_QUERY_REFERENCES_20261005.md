# 稳定查询编号与明确历史引用优先级

会话轮次新增服务端生成的q_加32位UUID编号。内存和SQLite保存不可变编号；SQLite旧表以增量列及唯一索引迁移，已有问题和状态不改写，旧记录编号仅首次迁移生成。清空、TTL失效或窗口截断后不复用旧编号，不以编号绕过会话隔离。

统一Omni响应在新增SQL历史记录时返回query_reference_id，首页提供“引用这次查询”填写入口。该按钮只填入前缀，用户仍需补充修改条件。未成功的SQL尝试也可能有记录编号，但引用仍须通过原有执行记录/来源版本/摘要核验，编号不代表执行成功。

ConversationReferenceAgent新增“回到SQL查询编号q_完整编号，那华南呢”；比较Agent支持“比较SQL查询编号q_完整编号和q_完整编号”，共享同一来源选择逻辑。重复问题可精确区分，不依赖动态倒数位置。比较来源显示稳定编号；不提供会话开头绝对顺序保证，不恢复已删除窗口外历史。

实测发现比较完成后，比较修改Agent先于明确历史引用截获请求，导致“回到编号”被误当修改比较对象。已修复优先级：所有明确SQL历史引用（含旧的倒数/完整问题和非法表达）跳过比较修改及融合继承，先由SQL引用核验处理，非法表达保持澄清。原比较功能不改。
