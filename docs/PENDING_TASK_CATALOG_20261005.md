# 多任务待补列表与明确恢复

新增独立`PendingTaskCatalogAgent`，以“查看待补问题”“有哪些问题没完成”等明确请求查看当前会话的未执行SQL任务。“继续没完成的问题”只给出选择，不猜最近一项。既有不完整“继续待补查询”仍走编号缺失澄清，避免新入口抢占原协议。

## 状态边界

- `PendingTaskStore.list_open`按任务root去重，只展示每项最新保留快照；相同问题的独立任务仍保留两项，不能按文本合并。
- 查看列表不追加对话历史、不执行SQL、不切换当前追问对象，也不续期待补快照或短历史TTL。只有主动选择稳定编号，恢复Agent才切换上下文。
- 复用`PendingTaskResumeAgent`核验来源版本和当前意图；数据源变化的任务仍可见但不可恢复。不通过列表重新授权旧任务。
- 已完成、过期、清空和其他会话任务不显示。完成一个root后其所有关联快照关闭，另一root保持。
- root仅内部使用，网页恢复使用完整`q_<32hex>`快照编号，不使用动态列表顺序。

## 前端

首页输入区和澄清补全示例提供“查看待补问题”；列表显示完整问题、缺少条件、保留时间与“恢复这个问题”按钮。查看列表后输入框保持之前的问题状态；新请求锁定旧列表按钮，恢复仍校验当前session。布局用分隔线。

文档工作台同类请求也展示可恢复列表，使用同一前端reference校验函数；其历史说明从“已继承N轮”改为“已保留N轮历史”，不从历史数量推断继承成功。两个页面继续使用各自现有会话标识，没有跨页面自动合并旧会话。跨入口统一会话选择仍需后续补齐，当前列表范围必须是当前API会话。
