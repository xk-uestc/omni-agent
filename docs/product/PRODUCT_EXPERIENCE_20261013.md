## 先使用，再修改

完整服务先运行在 `http://127.0.0.1:8030/`。A 使用真实浏览器上传与提问；B、C 通过运行中服务的真实 HTTP/SSE 执行。它们暴露的是用户流程、环境数据和模型执行的不同问题。

| 用户流程 | 前测实际结果 | 用户会困惑的地方 | 记录 |
|---|---|---|---|
| A：上传 PDF，输入“帮我分析这个文件。” | 上传后，聊天仍提示未检测到当前文件；没有完成文件到任务的衔接 | 上传成功与当前对话资料范围脱节；解析结果没有可操作入口 | 浏览器观察；[上传前测截图](screenshots/before-upload.png) |
| B：“统计数据库中工时最高的工种，并查询对应人工预算单价。” | `route=sql`、`status=clarification`；当前数据库缺少明确的“工种—工时”业务映射 | 用户不知道是缺数据、未规划成功，还是正在等授权 | `runtime/product_20261013/baseline-b.json` / `.sse` |
| C：“根据教材公式和参数计算运输保险费。” | `route=document`、`status=insufficient_evidence`，未完成计算 | 工具过程与模型规划失败原因不易理解；回答没有明确恢复路径 | `runtime/product_20261013/baseline-c.json` / `.sse` |

B 的现有演示库包含销售、人事、采购等表，但没有与教材人工单价语义一致的工种工时表。没有新增虚构数据把这一题包装成成功。

C 的诊断还发现部署层把规划输出限制在 2,000 tokens；这次上游响应为 `incomplete`，输出额度用于 reasoning，没有完整结构化计划。生产客户端拒绝不完整响应后回退到文档路线。这次失败不是“公式安全校验已通过但界面未显示”。部署层现已允许单次请求按原请求上限使用最多 5,000 tokens，并按相同上限预留预算；随后客单价公式与跨源任务已实际获得模型自主计划，见下方 `final-http/` 回执；这不替代运输保险费原缩略问法的同题验收。

## 产品与工程改动

| 方面 | 修改前 | 修改后与真实性约束 |
|---|---|---|
| 任务入口 | 普通聊天与多个工具演示入口混排 | 首页围绕五类任务引导；资料页将文件选择、解析摘要和提问连接起来 |
| 文件上传 | 按钮禁用，错误出现在页首 | 就地显示实际读取、上传解析中、成功或失败；没有虚构百分比、逐阶段打勾 |
| 资料范围 | 靠标题文字猜测“这个文件” | 明确的 `document_id`，服务端核对原件版本；资料范围冲突时停止并给出恢复动作 |
| 解析摘要 | 主要显示格式与片段数 | 真实页数、原生表格/表块、公式片段、索引片段；缺失统计不冒充零；仅图片占位不能标为可问答 |
| 质量反馈 | 内部英文警告直接暴露 | 映射为页级 OCR、表头、缓存公式和处理预算提示，附可执行建议；技术细节保留折叠入口 |
| 执行过程 | 原始 JSON 与通用“需要确认”混杂 | 展示真实工具开始/完成、来源与计算回执；条件不足、证据不足、服务错误分别呈现 |
| 最终答案 | 答案、引用与过程层级不清 | 结果优先，来源可点击，公式/参数/SQL依据可展开；单位未知时不补造单位 |
| 模型过程 | 容易把公开执行状态理解为模型“思考” | 只投影工具与任务状态，公开事件不输出模型 reasoning 或凭据 |
| 高级操作 | 预设依赖图与自主规划并列 | “手动工具链”默认折叠，明确是预设流程；不能将它表述为模型自主规划成绩 |

知识页的“取消文件限定，继续提问”只清空选择、回填原问题并聚焦输入框，由用户检查后发送。它不会自动触发新的模型调用。当前文件模式用于所选文档；数据库与跨源任务应切换为“全部资料”。

后端新增公共事件投影与所选文档处理，保留原 HTTP/SSE 终态和原件完整性检查。依赖任务在真实执行边界发布状态；依赖失败不会继续冒充下游成功。针对中文原生 PDF 中“数字换行后接量词”的来源连续性做了有界修复，保留原文片段、页面坐标及 SHA，不改数字、Gold 或原文件。

## 修复后真实 HTTP/SSE 复验

复验材料位于 `runtime/product_20261013/final-http/`；每项保留请求、完整响应和原始 SSE，汇总为 `summary.json`。六项均通过真实 TCP 请求到运行中的服务。五项达到各自验收断言；不限地区的跨源任务完成了自主规划与工具执行，但资料不足，**不计为完整任务成功**。

| 检查 | 实际结果 | 关键依据 | 耗时 / SSE trace |
|---|---|---|---|
| 文件概览 `overview` | `ok` | 明确 `local-warranty`；1 页、12 片段、4 条引用；`document_structure_overview`，明示是部分原文概览 | 0.092 秒 / 5 |
| 原生表格 `table` | `ok`，10.26 | `local-labor`、`native_table_literal`，保持原文数值与引用 | 0.567 秒 / 24 |
| 真实 PDF 问答 `real-pdf` | `ok`，10 场 | `model_grounded`，国家统计局原件第 1 页，4 条引用；原文数字换行得到来源支持 | 6.081 秒 / 24 |
| 公式 `formula` | `ok`，`fusion`、`model_validated` | 实际 `document_formula → sql → calculate`；4,188,944.0 ÷ 302 = 13,870.675496688742；公式、SQL 参数语义与单位均有校验记录 | 7.820 秒 / 15 |
| 跨源 `cross-source` | `insufficient_evidence`，`fusion`、`model_validated` | SQL 实际得到 2025 年冠军“东南”、销售额 6,280,960.41；再以该实体检索，当前资料没有对应经验，拒绝套用其他地区内容 | 17.538 秒 / 16 |
| 主动澄清 `clarify` | 按预期 `clarification` | 真实模型询问毛利/净利润口径、时间范围及维度，没有臆造数字 | 4.568 秒 / 8 |

公式演示的首次问题写了“去重订单数”，而文档和已配置指标为订单数 `COUNT`。复验明确使用与文档一致的“订单数”，实际 SQL 为 `COUNT(*)`，没有把去重要求静默改成计数，也没有取消语义校验。因此新结果证明的是 **COUNT 口径的文档公式跨源计算**，不声称首次 DISTINCT 口径已经通过。计算返回原始单位 `CNY*count^-1`。

不限地区的跨源任务已执行，但完整答案受资料覆盖约束。另尝试将华东、华南、华北限定放在句首和查询子句中，两次均因 `sql_document_plan_scope_invalid` 返回澄清（`additional-http/`、`scoped-http/`），未把离线合法图冒充模型自主成功。模型生成复杂筛选计划的稳定性仍是限制；没有放宽校验。

同题重测“根据教材公式和参数计算运输保险费。”已形成模型计划，但在执行前返回 `source_scope_unverified`，要求明确各参数的数据库来源，未计算成功，见 `additional-http/insurance.json`。主观上“应该能算”不能替代来源范围授权。

## 数据与资料的边界

| 来源 | 原件页数 | 实际入库结果 | 适合观察的内容 |
|---|---:|---|---|
| NIST SP 330 (2019) 国际单位制 SI | 138 | HTTP 200 | 英文长文档、单位、来源引用 |
| 国家统计局 2024 年政府信息公开年度报告 | 6 | HTTP 200 | 中文原文、数字与相邻行连续性 |
| 上海市水利工程设计概（估）算编制规定（2021） | 40 | HTTP 400，原件加密，拒收 | 真实失败反馈与可恢复建议 |
| 水利水电工程初步设计报告编制规程 | 152 | HTTP 200 | 中文行业标准、长文档范围与处理边界 |

最后一份标题已依据 PDF 首页纠正；旧本地文件名 `water-conservation-cost.pdf` 仅为下载标识，不能据此称其为“水土保持工程设计概算编制规定”。同一文档 ID 已用相同原字节重新入库，SHA 保持一致。

公开可下载不等于拥有再分发许可。本仓库仅提交官方 URL、SHA、大小、页数、许可说明与入库状态；PDF 原件只留在被忽略的 `runtime/`。没有下载整套数据集，没有修改 Gold。

当前原生表格批量入库上限为 **40 页/30 秒**。超过上限的长文件仍可进入文字检索，但不能声称已完成全文所有原生表格解析。公式片段数表示解析器发现含公式文本，不等于已验证、可计算公式数量。

`local-labor` 是既有冻结公开教材的单页材料：1 页、1 个原生表格。数据库为仓库演示数据；材料原价 500 CNY 与运输保险费率 0.02 是上一轮明确标识的人工集成映射，并非公开配对业务数据。它们不得与真实公开文档混称为真实业务效果。

## 实际环境与调用预算

- 系统为 Ubuntu 24.04.3、Python 3.12.3，项目 `.venv`；前端使用静态 HTML/JS/CSS，同源托管，无需 npm 开发服务器。
- 宿主 `nvidia-smi` 实测可见 **NVIDIA A100-SXM4-40GB，40960 MiB，驱动 580.178.04**。受限沙箱的同命令曾失败，不能据此写“本机无 GPU”。本轮部署没有使用该 GPU 做生成或训练。
- `/api/v1/documents/ocr/health` 实际 HTTP 200：`provider=rapidocr`、`ready=true`、`execution=local_cpu`，支持 Chinese/English。
- `/health` 实际显示 BM25、未启用 Dense；生成与规划配置为 DeepSeek `deepseek-flash`，没有配置警告。
- 用户本轮允许累计 **40 次模型请求、¥10 上限**；账本保留前轮调用，不按页面提问次数计数、不随重启清空。一条任务可能消耗多次上游请求。
- 交付快照累计 **35/40 次**，保守费用上界 **¥7.21897/¥10**；另有 5 次调用额度。浏览器后续提问继续计入同一账本，一条任务可用多次，快照不是实时余额承诺。
- 预算层使用保守费用上界，不是供应商实际账单。额度耗尽时不得自动绕过、重置账本或切换付费账户。

环境证据位于 `runtime/product_20261013/environment-probe.json`。真实密钥只从本机私有配置读取，不进入 Git、页面、截图或报告。
