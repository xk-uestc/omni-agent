# 可审计的选择性 OCR 融合原型（2026-10-05）

## 判断

已实现一条**独立离线原型**，不是已证实的 SOTA 模型，也没有替换 8030 正式服务。它把新版 RapidOCR 当首读，把 PaddleOCR 留给可观测的疑难页，把 MinerU standard 的 HTML 表格只当结构候选；候选行必须再由两个独立文字框、同行几何关系支持。原图 SHA、模型来源、坐标系和冲突状态均保留。

代码：`tools/ocr_fusion_trial.py`；反例单测：`ict-track8/tests/test_ocr_fusion_trial.py`；逐页输出：`D:\ICT8-OfficialDatasets\ocr-candidates\fusion-trial.json`。模型原始输出没有改写，见既有 `matrix-*/report.json` 和 MinerU middle JSON。

## 路由与核验

1. RapidOCR 首读。只有出现低于 0.75 的行置信度，或 `S100,000`、`$S0` 这类金额字形异常时，才选择 PaddleOCR 的整页结果。路由不读取样本名、真值或答案。
2. 出现明确“合计/TOTAL”且有至少四个独立金额框时，按需取 MinerU standard 表格候选。结构候选**不覆盖正文**，也不把整页某处出现过金额当成该行金额。
3. 每个双单元行必须在选中的文字引擎中找到两个独立框，金额位于标签右侧，并满足校准后的同行纵向误差阈值；缺失或冲突标为 `unverified`。合计只做单独的内部算术一致性检查，不证明单元值真实。
4. Paddle 旋转页坐标仍标为 `paddle_engine_output_unmapped`；当前只在该引擎内部核验同一行，**不宣称已映射回原图**。正式落地前必须补逆变换和裁剪可视化核查。

## 固定样本复放结果

使用上一轮已保存的真实推理输出，九个输入各两轮，输入 SHA 再校验。不是重新训练，也不是实时端到端压测；旧评分将换行删除后误判若干金额，本轮对数字改用**逐行边界**检查，三条链路按同一修正规则重算。

| 链路 | 公开字段命中 | 自建表格字段 | 预算顺序 CER | 已保存单次调用耗时之和 |
|---|---:|---:|---:|---:|
| Rapid 全量 | 206/210 | 80/80 | 15.79% | 56.0 秒 |
| Paddle 全量 | 210/210 | 80/80 | 1.68% | 1131.2 秒 |
| 选择性质量复核 | 210/210 | 80/80 | 1.54% | 249.0 秒 |
| 质量复核 + 表格结构 | 同上 | 同上 | 同上 | 679.3 秒 |

复核触发于 `budget-90` 与 `budget-lowres`，各两轮；结构候选触发于四张预算变体和两张中文表，各两轮。124/124 个双单元候选在所选文字引擎的框中找到同行支撑，12/12 张候选表的已观测数值内部合计一致。透视页 MinerU 另给出一个单单元日期行，未计入 124 个双单元行，也未假装有金额配对。

预算顺序 CER 只对一份公开 PDF 的同页变体计算，不能当整体 OCR 准确率。公开字段命中也不是完整正文准确率；九个输入来自少数独立文档，大量场景是同页派生，18 次运行不是 18 份独立材料。耗时是先前**隔离调用的数字相加**，不含本原型的真实调度、跨进程初始化、缓存竞争和并发；峰值内存不能按耗时比例推断。当前没有 GPU 或新官方标注集证据，故不能声称“达到 SOTA”。

## 反例与落地门槛

- 数字跨行、合并单元格、左右顺序相反或多级表头可能不能通过当前同行核验；应该保留冲突，不自动修数字。
- 结构模型和文字模型可能犯相同错误；`observed_pair` 与算术一致仍需独立标注集验证真实正确率。
- 正式服务已有来源 SHA、方向恢复与局部金额恢复契约。接入前需做 Paddle 坐标逆映射、裁剪图像逐行可视化、超时/内存预算和回退路径；不可直接把试验脚本放进 `ocr.py` 请求线程。
- 需要在未参与路由设计的真实中文财报、手写、透视、多页续表、公式和多级表头上盲测；重点报告**行金额精确率/召回率、定位误差、正文 CER、耗时 P95、失败率和成本**，再与 Rapid/Paddle/MinerU 单链路比较。

结论：这批样本证明**选择性复核可以保住全量 Paddle 的字段覆盖，同时显著减少需要运行 Paddle 的页数**；尚不能证明是通用最强识别方案。生产 OCR 未改动、未调用付费 API。
