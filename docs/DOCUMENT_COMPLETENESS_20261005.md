# 复杂文档回答完整性：逐项检索、缺失信息与连接恢复

## 本轮范围

针对完整性短板做一次可复现改进，未替换OCR、未重写NL2SQL规划器，也不宣称任意长文档全部达标。基线、所有中间失败和终版报告均保留。

## 已修改

1. 中文逗号、分号、独立问句，以及英文分号和换行的问题，识别为多个明确子问；不把实体列表、声明式条件和引号中的标点拆成独立问题。扩展部门、设备、要求等明确枚举问题的识别。
2. 回答前按明确子问查找原始资料，保留完整原问题作为主题与条件上下文、原来的文档和页码限制。每子问至多3条候选、至多6子问，生成仍按至多8片段、4来源及原有字符预算执行。导航是定位辅助手段，不是事实或完整性的证明。
3. 原文“没有记载预算”“No finance lead is stated”不能当作已取得该事实的完整答案。保留出处并标注证据不足。询问是否记载的布尔问题仍可作否定回答。
4. 保留逐字原文、实体/数值/条件核验、独立模型复核和原件版本重放，不用参考答案参与生成。
5. 结构化模型请求遇到连接中断或超时，允许完全相同请求的一次传输重试。HTTP拒绝、TLS错误、模型不符、响应不完整、JSON或语义失败不触发该重试。原NL2SQL适配器继续负责自身重试，避免双层叠加。
6. 重试次数与类型写入不含密钥的验收记录；响应丢失可能已消耗的用量明确记为未知，不能计作零。

## 保留的失败和限制

中间API试验出现连接失败，分别取得7/8、7/8和5/6、4/6等结果；没有删除失败、改评分或把参考答案注入证据。终版加入有界传输恢复后再次执行完整样本组。

公开OHR开发子集的初次候选复测仍为0/6精确匹配，token F1由历史基线0.231176降至0.114205，并伴随模型传输失败。最终6题全部执行、后端SHA稳定，精确匹配仍0/6，token F1为0.238215；相对历史基线仅增加0.007039，不能称明显优势。3题返回模型复核答案、3题证据不足；后者包含需要计算和完整表格关系的缺口。说明这些改进尚不能解决长表格完整枚举、跨行关系、跨页/扫描数值和需要计算的组合问题；不能用小型文本14/14宣布复杂PDF能力完成。最终复测另存`DOCUMENT_COMPLETENESS_OHR_FINAL_20261005.json`。

已读取的有限片段通过复核不代表未读取的整本文档不存在额外项目；4来源预算可能不足。有限缺失信息词表不是通用语义判定器，识别不到的隐含缺失或未知表达仍依赖模型澄清/复核。存在性问句与混合事实/存在性问题仍需要持续扩充测试。
