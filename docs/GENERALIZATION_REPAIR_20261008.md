# 多轮问答泛化修复与复测（2026-10-08）

本轮修复已部署到 `http://127.0.0.1:8031/` 和 `https://raysource.cloud/demo/`。当前服务启用真实 `gpt-6-luna`；能由实际 Schema、原件和完整条件独立核验的请求使用服务器编译流程，其他请求继续使用模型。测试使用合成演示数据，不是公开基准成绩。

## 修复内容

| 问题 | 实际修改 | 校验边界 |
|---|---|---|
| 指标、地区、年份连续追问丢条件 | 明确编辑先生成完整候选，再核对未改字段；支持确认尾句、裸年份、顿号及多个指标 | 矛盾确认、未知字段/取值、执行记录或数据版本变化时整条拒绝 |
| “销售额和订单数一起给出”被当成独立全库查询 | 将无“改成”动词的指标列表也识别为上下文编辑 | 必须核验成功历史与实际指标，原筛选完整保留 |
| 排名、分组 Top-N 不稳定 | 完整单表请求使用已核验编译器；普通列举动词不强制进入复杂模型规划；名次从真实排序指标取值 | 并列、新增未知条件、NULL 和多层聚合语义继续独立处理 |
| 年度比较只给百分比 | 明确绝对差额时输出实际本期减同期的“变化量” | 相邻年度且条件完整的有界比较；不把任意多年份比较擅改成同比 |
| 文档年份追问、SQL 排名衔接文档失败 | 保留唯一书名号来源、主题和时间；重绑定排名指标后重新执行 SQL 与检索 | 检验原文 hash 和数据库版本；缺少地区文字时说明原文缺失，不借用其他地区经验 |
| 排名与方法被当成因果证明 | 分别呈现数据库排名事实、所选地区方法和无法确认的因果 | 复核已保存成功融合来源，不能因同现就推导因果 |
| PDF 公式、Excel 参数、SQL 基准首轮依赖模型接口 | 来源唯一、完整基准、原件公式和单元格选择明确时直接编译依赖图 | 不预存答案、增长率或文档 ID；正常执行器重新核验整题来源、参数、单位和年份 |
| 情景参数标签不一致 | “积极/保守”等限定词保留；用户明确选择后，从当前原件切片重新提取同一指标 | 未选择情景、错误指标、伪造数值/引文/单位及资料变更均拒绝 |
| 情景切换后丢失原 Excel 来源 | 保留封印的原参数任务，比较时重新读取两套参数并执行同一 SQL 基准 | 不复用旧计算值；原选择器、来源版本和基准必须核验一致 |
| 最终答案缺少差额和预测边界 | 根据实际已核验计算结果组织主答案，显示两种口径、金额差额和“预测目标不能当作实际销售额”；前端直接显示 | 无额外答案生成 API；不会仅靠用户题目中的数字填充答案 |

主要源码：`pending_scope_edit.py`、`executed_scope_edit.py`、`sql_history_scope.py`、`ranked_result_followup.py`、`document_dialogue.py`、`unified_context.py`、`fusion_history.py`、`fusion_formula_planner.py`、`fusion_parameter_followup.py`、`formula_parameter_binding.py`、`dependency_agent.py`、`fusion_result_answer.py`、`omni_agent.py` 和 `nl2sql/engine.py` / `planner.py`。

## 限制

- 本轮没有重跑全仓测试，也没有证明任意复杂问题都能正确回答。
- 编译流程只接受能完整核验的语法、唯一资料、实体与参数选择；复杂关联、未明确条件、未知参数或含混资料继续模型规划或澄清。
- 复杂 RAG 仍存在较高延迟和上游接口波动。不能把快速 SQL/融合的耗时当成全部问题的耗时，也不能将开发样本通过率称为公开基准准确率。
