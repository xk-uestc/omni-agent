## 前端行为

| 来源 | 展示与定位 |
|---|---|
| RAG | 点击“定位 RAG chunk”，展开持久化片段；标记所引 chunk、高亮引文，展示 chunk ID、可用页码/行号/位置、前后相邻片段及原件链接 |
| PDF 原页引用 | 缺少 chunk ID 时根据原引文与页码定位入库片段；无法匹配则明确说明原页直接读取，不生成虚假 chunk |
| SQL | 显示实际数据库、物理表与实际使用字段；展开表读取前10行原表预览，表头标记 SQL 使用字段，数据格只高亮符合本列筛选条件的值，并提供原 SQL 与参数 |
| 结果追问 | 沿用核验结果时保留原执行来源，明确标记复用，不伪造新执行 |
| 联合查询 | SQL 子任务及 RAG 检索引用分别接入来源组件 |

预览中的10行是原表样例，不是本次过滤或聚合结果。实际来源从执行 SQL AST 解析，CTE 等虚拟表不作为物理表展示。片段及数据表按需加载，关闭可中止前端请求；宽表在卡片内滚动。两页面资源缓存版本更新为 `20261007-sources-3`。

## 接口与来源版本

- `GET /api/v1/nl2sql/tables/{table_name}/preview`：必传 `expected_source_revision`，只读查询真实表；limit 默认10、范围1—25。
- `GET /api/v1/knowledge/documents/{document_id}/chunks/{chunk_id}`：必传 `expected_source_sha256`，返回精确 chunk 与前后各一个相邻片段。
- `POST /api/v1/knowledge/documents/{document_id}/source-location`：原生引文定位，核验文档 SHA，返回匹配的持久化 chunk。

数据库或文档版本已变化时返回409，避免旧答案被定位到新原件。原生引用定位允许 NFKC 与空白归一，仅用于导航匹配，不改动展示的原文、不将匹配视为答案语义正确性证明。
