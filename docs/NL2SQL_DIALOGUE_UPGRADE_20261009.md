# NL2SQL 对话上下文升级实测记录

日期：2026-10-09。范围：本地对话槽位解析、成功 SQL 范围继承与引用；不包含公开基准成绩或外部模型吞吐评测。

## 实现

- `ict-track8/backend/conversational_sql_edit.py`：新增有限语法的本地追问解析。将“同样条件，2024年，华南，订单数”“只看华南”“华南也查一下”“再给我订单数，其他条件不变”等转为已有原子编辑命令。
- `executed_scope_edit.py`：这些命令仍经过原成功查询的执行凭证、当前数据版本、保存字段、独立完整范围解析及未修改条件核验；不能消费全部文字或不能唯一识别字段时整条拒绝。
- `sql_history_scope.py`：核验分组物理表、列与时间变换，避免同名列或年/月粒度漂移；“各地区/每个品类”等省略“分组”字样的原查询现在能安全改成新分组。
- `history_reference.py`：接受“回到刚才那次数据库查询”“接着上一条问数查询”等明确 SQL 来源表达；查询编号、倒数位置、完整问题引用保留原安全契约。
- 明确“同样/相同条件”仍属于依赖原查询的追问，不能在原查询失败后变成丢失原筛选的完整独立 SQL。
- 完整新问题中的“仍是/还是”前缀可作为口语强调，但只在本轮同时给出指标、时间与实体/分组时成立；省略条件的确认仍使用原继承守卫。

`test_single_sql_task_discarding.py` 的旧预期强制追问 `planner_source=model_validated`。已有实现会在服务器完整核验追问后使用 `rules_basic`，因此改为断言额外规划 API 调用为 0、完整物理 SUM 指标、2025 年半开时间范围、华南筛选与没有执行冗余任务。此项是修订已有过时测试契约，不计作新增用户能力。

独立冻结评测 `candidate-2.json` 的 `history-group-08` 曾拒绝“换成按地区分组”：短句同时链接明确的 `sales_orders.region`（0.74）和较弱的自动画像建议 `regions.region_name`（0.59），旧逻辑将其一律视作同权歧义。修复采用与指标链接一致的同别名最高分规则，并继续要求完整范围解析的目标物理表/列相同。相同分数的多个物理归属仍拒绝。新增完整冻结 8 轮整链测试逐轮匹配独立 SQLite gold SQL，另以相同分数的多表候选验证不能按列表顺序选字段。

## 派生指标上下文补强

原历史层将一个已声明派生指标的多个真实依赖误认为多个用户指标，并把合法指标替换导致的 `derived_metrics/output_metrics` 变化一律拒绝。现在按完整别名计语言槽位，但必须独立核验该别名的全部物理依赖、聚合函数、业务元数据、公式和输出。仅用户明确替换指标时可改变公式及输出，时间/地区/分组追问仍要求原公式完全不变；排名、HAVING、排序方向等其他控制继续保留。

真实 rich 数据库经 `OmniAgent.query` 实测“2025年华东销售额 → 本金呢 → 那华南呢 → 换成毛利 → 看看订单数”全部成功，每轮与独立 SQLite SQL 对比。这里的销售成本仅使用演示数据已声明口径 `SUM(sales_amount)-SUM(gross_profit)`，没有把金融本金设为通用成本同义词。其他新例包含客单价、平均每件收入、毛利率与网站转化率，验证切换公式、继承筛选和切回基础指标。

派生成功执行凭证新增 `metric_semantics_sha256` 和 `metric_catalog_sha256`，绑定真实已执行计划的公式、依赖和指标口径。历史授权函数也重解析核验该凭证，防止 Catalog 在数据库文件未变化时把旧查询静默解释成新公式。普通旧记录保持兼容；没有公式凭证的旧派生记录需要先完整重查，不猜测其原业务定义。

另修复同表多个聚合 CTE 被误识别成跨表查询的路由问题：只按 SQL Scope 中真实物理 `Table` 来源计数，CTE 名称不再增加表数。真正的跨表编辑仍走原参数绑定安全校验。派生指标和真实跨表联合 38 项通过，最终全部历史专项联合 357 项通过。

## 性能与边界

新增本地语法不调用模型；独立完整新问题在语法入口即退出，不新增 Schema 读取。已核验追问的模型请求数有明确的零调用断言。用户指定字段和数据库实体必须有真实 Schema/值依据；未知词或复合表达仍会请求澄清，不能保证任意自然语言全部自动成功。

历史引用继续受会话隔离、保留窗口和来源版本约束。没有执行凭证、来源已变、重复完整问题引用或未成功的目标 SQL，都不会改用其他查询或猜测范围。
