# SQL待补任务独立保留

本轮解决普通聊天默认8轮/30分钟保留限制导致未完成问题无法恢复的问题。

## 行为

- 普通聊天历史仍为最近8轮、默认30分钟，不把长期待补内容自动塞入模型上下文。
- SQL待补条件快照独立保留，默认24小时；每会话最多64条条件记录（包括修改和恢复的快照），会话数量受max_sessions限制。
- 通过完整待补编号显式恢复，重新解析指标、字段、筛选条件与澄清原因；不匹配时拒绝恢复。
- 同一个待补任务的修改、说明、补选及恢复快照关联同一任务；成功执行后关闭全部仍保留的关联编号。SQL执行失败不关闭。
- 编号仍代表该轮历史条件。恢复旧编号不会自动采用随后修改的新条件。
- 修改或恢复不会延长原任务24小时期限。记录超限时淘汰最旧记录；完成状态也受同样期限和数量限制。
- 清空会话或reset_context删除该会话聊天及待补记录；普通聊天TTL过期不会删除待补记录。独立提问按钮目前使用reset_context，因此也会清空。
- SQLite模式的聊天写入、待补快照保存及完成状态更新处于同一事务；内存模式保留同样的有限生命周期。

## 边界

当前只扩展普通SQL待补任务，不扩展文档、跨源或比较流程的长期待办。升级前未进入独立待补表的旧编号不能保证恢复，应重新提交问题。已完成SQL的历史引用仍受普通历史窗口限制。多worker依然需要共享锁/CAS；本轮没有实现。未重跑全项目套件及真实浏览器点击验收，局部开发验收不是官方分数。
