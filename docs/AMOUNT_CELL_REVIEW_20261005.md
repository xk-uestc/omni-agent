# 金额单元格的局部OCR复核

## 行为和架构

新增独立 `AmountCellReviewAgent`。仅对已有矩形表结构中含币种标记但不能明确解析的OCR金额做局部复核；清楚的金额不盲目重复识别。只接收原始图像、单元格结构与行识别器，不接收总计推测值或目标金额。

核对原图SHA、原单元格凸四边形、位置资格和图像范围；将原单元格四边形映射为正向行图，留两像素网格边界余量，以可见墨迹收紧空白范围，保存原多边形、收紧范围、裁剪SHA及输出尺寸。原色、2倍放大、灰度增强对比三种不同像素预处理分别调用RapidOCR行识别，跳过重复像素SHA。

至少两个不同预处理的完整有效识别需要同金额/同币种、置信度>=0.85；所有有效尝试必须一致。多个值、低置信度、失败或超时、标点仍不明、候选冲突均不能发布候选，不以多数票或合计推测选择数字。

最大4个疑点、每格最多3次、调度预算默认20秒（不是硬中断正在进行的推理），有原图/裁剪像素预算。不可用执行器或来源不符返回复核不可用。RapidOCR提供线程锁保护的局部行识别方法，不重新跑网格检测。

原OCR结构和全文保持原值；独立`revised_preview`保留原格与候选对照、合计重算。候选没有单独金额真值核验资格，仍`cell_values_verified=false`，并明确声明多预处理使用同一个OCR模型，不是独立识别器。未自动修改资料库或生产SQL输入。

图片OCR接口和PDF表格预览均接入；PDF局部复核仍要求重渲染图SHA与原单元格来源一致，否则拒绝。前端显示原值→候选/复核失败、逐次识别与裁剪证据，并把候选合计与原OCR合计分开。

## 发现与验证

首个直接真实局部试验整格空白太宽，三次行识别置信度不足，正确未接受。保留单元格内可见墨迹范围后，公开预算页Office Supplies三次均识别`$2,000`，置信度约0.9964、0.9997、0.9951；原页OCR仍为`$2.000`。候选合计一致来自识别后的单独计算，未指导行识别。

最终相关后端199 passed、1个既有Starlette/httpx警告；knowledge语法和跟踪资源whitespace检查通过，实际HTML/JS哈希与本地一致。回归涵盖一致候选、不改原格、低置信度/多个值/歧义/失败、候选冲突不多数选择、外来SHA/非法坐标、旋转多边形和无执行器不伪造。

实际脚本：`tools/verify_amount_cell_review_http.py`，公开源PDF SHA `7386776d1a2bada2f9d8068dec77c79e0ff832d90af6cf2c869f84651065b4bd`。原页光栅化、90°和5°旋转均为同一个公开页的受控图像变体，不算三个独立公开文档；只核查Office Supplies目标金额、接受候选来源及合计，不称全页OCR准确率。

同一识别器可能在三种预处理上给出相同错误，候选不是扫描金额的独立真值证明。跨页断行、自动表头、不同单位及原生复杂跨页盲测仍需继续。PDF接入目前主要由已有单元格/PDF结构回归支撑，本轮实际接口优先验证图像场景，不混称PDF新路径已完成实测。没有浏览器点击、全量项目回归或官方成绩，整体目标保持未完成。
