# 现场演示与失败边界

本项目独立运行于8030。样本为CC0合成文件；问数数据库为可重建演示数据，Chinook为公开开发库。
当前gpt-6-luna鉴权401，以下默认规则/摘录流程可以实际运行，不声称模型已通过。

## 启动

1. 根据README安装依赖，运行tools/run_server.py。
2. 打开根页面，查看Schema和问数结果。
3. 打开knowledge.html，确认15份实际文件、原文件链接。
4. 打开capabilities.html，展示实现证据与未完成项。

## 真实模型就绪后的追加演示

先运行tools/probe_model.py，仅当/v1/responses结构化探测通过时运行tools/evaluate_model.py --full。
再用--with-model启动；演示纯文档生成、三源预测、历史版本比较和通用跨源追问。
每题检查planner_source=model_validated与answer_mode=model_grounded。extractive_fallback不能记作模型成功。

## 突发情况

- 401：不改模型、不读取其他凭据；检查本地runtime/model_config.json的服务鉴权。
- OCR不可用：显示执行器失败，不把占位图片当文本。
- 年份/单位/版本冲突：停止依赖链；展开trace定位具体失败步骤。
- Dense资产缺失或哈希错误：停止加载并根据公开manifest恢复，不使用未核验权重。
- 原文件哈希变化：停止原文回看，确认资料归属再重新入库。
- 对话条件不符：开始新对话，不能修改后台事实凑答案。

## 比赛答辩必须说明

规则成绩、模型成绩、公共库开发题与官方未知题分开；10种OCR扰动不是OHR-Bench。
500页文字PDF、在线本地混合检索、外部生成和全量OCR四种成本分开。
当前未见题准确率、行业领先性、获奖等级均没有充分独立证据，不能根据内部通过率换算。
