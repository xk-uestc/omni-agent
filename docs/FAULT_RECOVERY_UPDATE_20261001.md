# 原文件证据与实际故障恢复验收

本轮在临时资料、演示库和独立 HTTP 子服务上注入真实故障。首次完整结果为 4/10；修复后相同输入为 10/10。首次失败保存在 `FAULT_RECOVERY_FIRST_RUN.json`，当前结果保存在 `FAULT_RECOVERY_REPORT.json`。修复后的结果属于开发回归，不称为独立盲测。

## 实际发现与修改

| 缺口 | 修改 | 验证 |
|---|---|---|
| 原文件被改动或删除后仍可从旧切片取证 | document、公式取值和最终检索命中的来源重新核对 SHA-256；限制路径和符号链接 | 篡改/缺失时停止，恢复后相同链成功 |
| SQL 存储异常未统一进入失败状态 | DAG 区分 evidence_integrity_failed、storage_unavailable、tool_contract_failed | 缺库和独占锁使后步 skipped，无最终数值 |
| 会话库锁定时接口异常不明确 | HTTP 503、Retry-After: 2，隐藏本机存储路径，不降级到新内存会话 | 解锁后历史保持，原追问继续 |
| SQLite with 仅结束事务而未关闭连接 | engine 使用 finally close；初始化使用 closing | 正常与异常退出均立即关闭连接 |

来源校验只针对选中的文件，避免每次全库哈希；不缓存“通过”状态，防止文件被改动后继续复用旧证据。哈希证明文件与入库时一致，不证明内容本身真实，也不能替代引用语义核验。

## 十项实际故障检查

1. 篡改原文停止公式链。
2. 篡改原文停止 RAG 旧切片回答。
3. 删除原文停止公式链。
4. SQL 数据库缺失停止依赖步骤。
5. SQL 数据库独占锁停止依赖步骤。
6. 恢复文件与解锁后相同工具链成功。
7. 强制 kill 子服务后重启，五轮地区、时间与指标上下文继续。
8. 未选择的澄清候选跨硬重启继续完成选择。
9. 会话 SQLite 独占锁返回脱敏 503 和 Retry-After。
10. 解锁后历史不变，追问继续。

用例签名：`e5045a11a0300d44f991c9c9bf659b4e4c61c8be5d59c524165b3db9bc8ac213`。脚本首次调试中的中断不作为完整结果；这里的 4/10 指完整首次报告。

## 复现与限制

```text
python tools/evaluate_fault_recovery.py
python -m pytest ict-track8/tests -q
python tools/evaluate_independent.py --dense
python tools/evaluate_rag_scale.py --work-dir <空间足够的临时父目录>
```

所有故障只作用于临时副本；不代表掉电、磁盘损坏、多机容灾或所有生产故障均已覆盖。指定 gpt-6-luna 的真实 API 仍为 401，未知自然语言任务、多源模型五轮与模型端到端成本未验收。正式材料使用当前证据重新生成，组委会模板和实际初赛反馈仍待提供。
