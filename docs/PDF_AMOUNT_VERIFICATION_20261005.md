# PDF表格金额的独立文字层核对

## 实现与边界

新增独立 `PdfAmountVerificationAgent`，接入PDF逐页表格预览。按原PDF SHA、页号和单元格未旋转坐标，从PyMuPDF原生文字层独立提取词框，不使用OCR全文作为参照。每个数据锚点附加 `amount_check`；表级汇总 `amount_verification`，跨页拼接沿用各格的原页核对证据。

比较使用Decimal，支持显式币种/符号、严格千分位、0到2位小数、符号前后负号和括号负值。不猜`$2.000`是2000或2，不猜欧洲/英美标点格式，不把裸数字或两个金额当单一金额。单独`$`和`¥`保留符号身份，不推断USD/CAD/AUD或CNY/JPY；符号与具体币种混用进入复核。

状态：

| 状态 | 含义 |
|---|---|
| matched | OCR与同位置原文字层金额一致 |
| conflict | 可明确解析的数值或币种冲突 |
| needs_review | OCR缺失/标点歧义或币种身份不明确 |
| unavailable | 独立文字层、位置或可解析参照不可用 |
| not_applicable | 不含可核对金额的普通文本格 |

词中心必须在原单元格凸四边形内，所有词框角点必须包含或处于最大0.5pt的边界舍入容差内。超界词不跨格归并；非有限、退化或自交多边形、不同SHA/页、失去定位资格、词数超预算等不能核验。每页最多20000个词、每格最多32个参照词，保留实际原文、词框和金额解释，不静默改写OCR。

网页逐页/跨页表格附加绿色“与原文字金额一致”、红色“金额或币种冲突”、橙色“金额需复核”、灰色“金额未独立核验”，悬停显示原文字与OCR。原生文字层也可能错误或属于旧OCR层，因此一致不等于真值，`cell_values_verified`、`ready_for_sql_import`仍为false。

## 验证

最终相关后端 **163 passed、1个既有Starlette/httpx弃用警告**，前端上下文/会话/请求/SVG/续表/金额标记 **63 passed**，knowledge语法检查通过。测试包含Decimal及负金额、币种不推断、标点歧义、缺失/多金额、来源与页号、越界与0.5pt舍入、坏多边形、真实原生PDF独立提取和无原文字拒绝。页面HTML/JS/金额脚本的实际HTTP哈希与本地一致。

实际验证脚本 `tools/verify_pdf_amount_http.py`，使用公开OHR预算PDF原件，并区分两类受控验证：真实HTTP返回的OCR结构人为改写金额/标点后直接送入Agent，及原页光栅化无文字层扫描件HTTP。金额及标点污染不能伪装成天然OCR失败；扫描变体不等于新增独立公开样本。原件SHA `7386776d1a2bada2f9d8068dec77c79e0ff832d90af6cf2c869f84651065b4bd`。

首轮开发报告`runtime/pdf-amount-http-7d5c7f42dcf94f2084c05b71408d49fc.json`各案例通过，但运行期间继续完善币种/负金额规则导致源码不稳定，不用作终版证据。负金额扩展时旧拒绝测试未同步，1失败/28通过的中间结果已修复；终版以最终回归为准。
