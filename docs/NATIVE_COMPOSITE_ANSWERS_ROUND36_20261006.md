# 文档复合计算与原生图表类别比较

## 程序改进

- 最高／最低项比较不再受普通12项加法预算误限；最多256候选，仍只允许同原件、同页、同表、同列、同期间、同单位，全部并列项保留。普通加法仍限12项。
- `sum_percentage` 从多个原始分项相加，再除以明确打印的总额；`max_plus_percentage` 先对完整候选集合找唯一最高项，再加指定项、除总额。服务端Decimal／Fraction运算，保留有理数、原值、角色、逐步计算和舍入规则，不制造虚构原件单元格。
- 明确指定项必须在原问题中唯一、完整、按词边界命中同列原始行名。修正模型的角色ID错误时保留原proposal与字面匹配范围；未知别名、不唯一名称不猜测。完整问题及候选仍需独立审核，不能只凭字面匹配判定整问正确。
- `native_label_amounts.py` 支持原生文字中明确“类别名, $金额”的相邻换行绑定，包含旋转PDF显示坐标和原生字词证明。它仅支持类别极值比较，整页候选集合不冒充同图证明，不推断图表货币倍率，不支持金额加法或物理数值查询。
- 来源前缀 `In …, which …`／`Within …, which …` 仅用于语法分类，原始问题不被裁剪；它的来源限制完整进入选择与审核。
- 普通金额／加法问题的选择目录不提供仅能比较类别的分散图表事实，避免模型错取无倍率的图表金额，再跳过有明确单位的表格；原始完整页文仍保留给审核。新增图表＋带USD million列头的同页混合反例确认金额读取保留单位和倍率。
