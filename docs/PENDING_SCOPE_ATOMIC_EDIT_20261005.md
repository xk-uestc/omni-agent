# 待澄清任务的条件修改与一次完成

## 独立Agent边界

新增`PendingScopeEditAgent`和类型化决策`PendingScopeEdit`。它只修改当前会话最后一条普通SQL待澄清任务；比较子流程继续由原有比较Agent负责。Agent核对保存的待补问题、澄清类型、筛选、指标与分组是否和当前重新解析一致，不执行SQL、不请求模型补默认值。

支持明确的时间、唯一物理字段取值和唯一指标修改。例如“那把时间改成2024年吧”“华东改成华南”“销售额改成订单数”。命名字段依据当前Schema核对，不局限于地区/渠道；“品类改成耳机”也有完整恢复测试。缺失的明确时间可追加，原请求其他文字保持不变。

一次请求最多四个明确分句、160字符。各分句形成临时候选，所有修改成功后才保存；未知取值、错误字段名称、重复修改同一条件、非法日期、排除条件、注入文本或末尾不支持的选项均整批拒绝，原问题不部分更新。

修改与澄清选择可一起发送，选择依据每一步候选问题重新生成的唯一当前选项，不使用旧按钮内容。支持“时间改成2024年，地区改成华南，指标改成订单数，按月统计”，也支持先选择粒度再修改时间。选择后仍有缺项则继续澄清，所有条件齐全则进入正常Omni模型规划、语义校验和只读SQL执行链，不直接用旧SQL授权执行。

## 会话与网页

每轮保存修改后的完整问题，SQLite对象重建后继续补选会使用新条件，失败整批修改不会丢失原条件。其他会话、reset_context及独立新问题不进入待任务编辑；显式新话题不被本Agent拦截。

返回实际Agent来源、修改前后的条件、是否已经执行，以及逐项修改记录。首页显示年份、筛选值、指标和粒度的变化；原来未指定的时间或粒度显示“未指定”。未完成的请求明确提示补齐后再执行，成功请求展示本轮实际完整问题。
