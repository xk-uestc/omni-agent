# ICT 第三届产业创新大赛赛题八设计说明

## 1. 目标与边界

本实现面向“自然语言访问结构化数据，并联合企业文档给出可解释答案”的赛题八
场景。核心目标不是只返回一个数，而是同时返回：问题改写、字段链接、只读 SQL、
参数、结果行、文档来源、证据角色和可展开的执行 trace。

当前仓库提供可复现的本地基线和生产 HTTP 检索适配器。真实 OCR 服务、真实比赛数据、
生产 UI 共享会话和网络/模型延迟没有被本地夹具冒充为已完成。

## 2. 总体架构

```text
用户问题
  -> 可选有界 session 上下文（无 session_id 时无状态）
  -> 意图与字段链接
  -> 外键图路径规划（最多 4 跳）
  -> 只读 SQL 安全门 + SQLite authorizer
  -> 结构化结果与 provenance
       \ 
        -> 文档查询改写 -> 本地 BM25 或生产 /retrieve -> 证据标准化
  -> 结构化/文档证据融合
  -> answer + trace + warnings
```

文档质量链路独立于 SQL 链路：文本/页面质量评分、图片质量探针、白名单图像预处理、
PDF 文本抽取、页级 OCR 重试计划均只输出可审计信号；没有 OCR 结果时不会伪造文字。

## 3. 关键设计选择

| 设计 | 选择 | 原因 |
|---|---|---|
| 数据库访问 | SQLite 只读 URI、参数化查询、authorizer | 防止写入、注入和长时间失控执行 |
| 多表关联 | 基于真实外键的双向 BFS，默认最多 4 跳；模型计划也必须走同一图校验 | 自动补中间表，拒绝无外键猜测和任意 JOIN 条件 |
| 文档召回 | 本地轻量 BM25；生产走 HTTP 适配器 | 中文短片段、标题和 IDF 可解释；审计事件透传真实 BM25 原始/相对分数，明确不伪造 Dense/RRF/rerank |
| 多轮上下文 | `session_id` 显式启用，8 轮/30 分钟/512 会话上限 | 防止不同用户串上下文和内存无限增长 |
| 低质量文档 | 页级原因、变换顺序和最多 3 次 OCR 重试计划 | 先增强再交给外部 OCR，保留失败升级边界 |
| 降级 | 外部检索失败返回 `partial` 和 warning | 不把空证据或本地夹具伪装成生产答案 |
| 周期比较 | 参数化同比/环比条件聚合 | 明确周期才执行，避免用当前日期猜测 |
| 模型接入 | 可选 HTTP JSON 计划提供器 + 规则回退 | 模型只提交计划，不提交 SQL；服务异常不阻断基线 |

## 4. 赛题适配证据

- 结构化问数：单表聚合、时间粒度、`HAVING`、平均值子查询、去重计数、同比/环比窗口。
- 模型规划：版本化 JSON 计划契约和可选 HTTP 提供器；表列、聚合、过滤、日期窗口和外键路径均由服务端复核，失败自动回退规则基线。
- Schema Linking：真实字段/别名和外键图；测试覆盖三表两跳路径及断开表澄清。
- 文档问答：政策、流程、字段说明、公式、FAQ、扫描质量、多语言、图像证据等 11 类
  离线夹具；生产 `/retrieve` 响应转换为统一 `DocumentHit`。
- 解释性：四阶段 trace 记录原问题、有效问题、规划、SQL、参数、候选分数、命中词、
  来源和证据角色；流式接口额外发送右侧审计兼容 `audit` 事件，独立 Demo 可展开查看
  完整 JSON。离线链路只声明 BM25 通道，避免把不存在的 Dense/RRF/rerank 展示为事实。
- 质量鲁棒性：旋转、倾斜、模糊、OCR 置信度、替换字符、空页均有页级决策。

## 5. 可复现验证

当前本地回归测试为 308 项（另有 1 个第三方弃用警告），覆盖 SQL 安全、JOIN、跨源融合、会话、图片预处理、PDF、
OCR 重试计划、模型计划安全门、同比/环比、生产检索响应契约和源码交付包重建。结构化基线和本地文档页基线分别记录在
`docs/ICT_TRACK8_PERFORMANCE.md`。
