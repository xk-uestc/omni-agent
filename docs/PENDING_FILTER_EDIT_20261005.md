# 待补查询：筛选增删与复合修改

本轮只打磨多轮澄清与上下文，不将开发样例成绩当作官方准确率。

## 用户可见行为

- 尚未执行的SQL待补问题可输入“增加渠道筛选为线上”“删除地区筛选”。字段别名、真实表字段和精确取值须唯一对应当前数据。
- 可与已有时间/指标替换及当前粒度选项组合。例如先问“2025年华东销售额趋势”，再说“删除地区筛选，增加渠道筛选为线上，时间改成2024年，按月统计”。
- 最多四项明确修改；全部可核验才应用。未知取值、重复修改同字段、字段取值不匹配、冲突筛选均保留原问题，不执行SQL。
- 删除排除条件须删除完整否定短语，避免留下“排除”改变其余语义。无法唯一确认范围时拒绝。
- 同值新增保持幂等，正向新增不能覆盖负向排除。
- 完成后关闭关联待补任务，旧编号不会再次执行；仍受当前会话和数据来源版本核验约束。
- 首页澄清区提示修改语法；已核验新增/删除分别显示“未设置→取值”“取值→已移除”。同值保留不显示虚假变化。

## 实现

`PendingFilterEditAgent`独立解析增删，修改前后重建查询意图，核对其他筛选、指标、分组、表和查询控制，不自行调用模型或执行SQL。`PendingScopeEditAgent`负责整批原子应用，`PendingSourceValidationAgent`核验来源版本。
