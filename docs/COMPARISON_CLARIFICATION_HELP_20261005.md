# 比较任务的说明与确认语恢复

## 本轮行为

比较任务等待修改对象时，原先的普通“好的/怎么选”没有进入比较修改分支，可能丢失当前任务。本轮由既有ClarificationContinuationAgent提供有界回复识别，比较Agent继续负责验证已封存的两侧来源、来源版本、修改对象与待补查询。

- 等待“基准查询还是比较查询”时，确认语/不确定回复保留原改动，例如“换成2024年”，不改成“好的”，不执行SQL、不替用户选择。
- 解释基准值、比较值和差值的意义；前端增加修改对象说明与取消入口。
- 已选中一侧但缺年份、粒度或字段时，说明请求、确认语、不支持的粒度经过普通SQL澄清Agent处理，保留该侧完整问题、封存的待补状态和另一侧结果。
- 任一来源变化仍在说明之前拒绝；取消使用原比较结果，不重新执行两侧SQL。
- 比较编号继续用于稳定任务身份；SQL历史引用Agent按route筛选，比较编号不能作为成功SQL来源。修正既有“不应存在编号”的过期断言，并新增编号类型隔离验证。
