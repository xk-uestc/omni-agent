# 比较任务中断后的长期恢复

## 行为与架构

原普通 SQL 待补目录没有归档比较查询，其他话题打断或短聊天历史过期后，比较对象选择与双侧修改中间状态无法按稳定编号找回。本轮增加独立 `PendingComparisonResumeAgent`，复用有期限和容量限制的任务存储，比较任务也进入“查看待补问题”目录。

恢复前检查原比较来源、实际执行快照、数据库版本和指标定义；待补子查询检查封装摘要、来源版本、对象索引及当前澄清类型。双侧修改验证已完成侧的快照与未完成侧对应上下文；不会把暂存结果提前发布。

- 纯恢复不执行 SQL，重建原选项和修改对象。
- 明确编号加补选可进入原比较 Agent，不使用最近一次无关查询。
- 补充不明确时保留原任务，不自行猜修改哪一侧。
- 完成或取消关闭同一根任务的所有编号，不再作为待补任务执行。
- 取消修改对象选择也可恢复原比较，无须重新取数。
- 恢复继承原任务过期时间，不因浏览或恢复无限续期。
- 会话隔离、清空与容量仍由原任务存储统一管理；新状态封装不发送到模型规划历史或前端。

存储表沿用 `pending_sql_snapshots`，兼容已有普通SQL任务，无须破坏性迁移。旧版本尚未归档的比较任务不会自动补出记录。

## 证据

最终相关后端回归 **256 passed、1 skipped、1 warning**，覆盖任务目录/恢复/存储、比较/双侧修改、会话、普通澄清与条件编辑。警告为既有 Starlette/httpx 弃用提示。初次99通过/2失败源于测试手写参考数错误，已改为直接独立SQLite SUM参考；不得据此宣称修复了生产查询数值。

新增比较恢复专项含内存及SQLite两模式：聊天过期、重建Store、修改对象选择、纯恢复不执行、双侧已完成一侧暂存、两侧完成后的分组对齐不重复执行、取消、未知回复、跨会话、期限、来源变化和封装损坏；通过真实FastAPI澄清入口验证连续时间→粒度补选返回比较子流程。

真实8030服务使用用户授权gpt-6-luna运行 **11/11 HTTP轮通过**：两项来源查询→比较→对象待补→无关查询打断→目录→跨会话拒绝→纯恢复→选基准完成→目录关闭→旧编号拒绝。来源与完成后的数值/差值由独立SQLite参考核对，前后源码哈希稳定。

本轮未改前端，复用上一轮已验证的稳定编号恢复按钮；未做浏览器点击验收、项目全量回归或官方盲测。实际HTTP验证了话题打断；期限及进程重建由隔离内存/SQLite测试验证，不能混称为实际长时间等待证据。

## 尚未完成

比较恢复只接受明确编号与可核验的修改/补选表达式，任意多对象自然指代的泛化效果仍未证明。文档/跨源长期任务、完整历史回答重绘、跨设备会话同步仍缺。低质量文档仍需自动多级表头、真正跨页拼接、独立金额/单位核验与更多真实低质量原件盲测；本轮没有改善或重测文档识别准确率。整体目标继续未完成。
