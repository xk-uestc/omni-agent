## 实际形成与复用

最终轮B种子由真实Agent自主生成SQL排名→文档检索计划，当前工具完整执行后，经独立SQL/实体/原文/来源评分；随后以原问题重执行该真实计划，保存模型审计与图digest、工具轨迹、评分器SHA及独立反馈，经实际管理员CLI子进程验证/确认。目标会话重建Store与ConversationStore，提示只含方法角色、依赖和当前参数来源；原Omni Planner必须重新生成完整图。没有目标前put注入、没有旧SQL/数值复放。

最终公式种子因模型输出非法JSON（错误转义、DSML标签）被拒绝，客单价开发图因source_scope_unverified被拒绝。故最终可信池只有1条真实模型形成的B经验，而不是设计期希望的多种方法。中止轮曾形成A/B及研究者替代顺序种子，单独保存，未拿来回填最终池。研究者种子明确标为developer_verified_seed。

预定义“应覆盖的经验任务”指标B/C均15/16，唯一缺口d01为公式种子未形成；这同时反映库存覆盖，不能全归咎于选择策略。最终合法池内四次选择均合法，其余拒用/不使用，没有过期或非法ID使用。d08/h08因公式空池而是空对照，不足以证明真实撤销；额外对最终真实确认的B条目执行来源改变、可信撤销、换project，3/3拒用，详见verification.json。单测另覆盖Schema、篡改、工具不可用、未审核、审批期间来源变化及撤销重放。

## 失败归因与回归

- 四类手工完整约束诊断：A/B能执行，C动态过滤source_dynamic_binding_unverified、D整题来源source_scope_unverified。只跑不带original_question的图会隐藏C/D障碍，本轮未绕过校验。
- 真实最终轮JSON协议失败次数A2/B4/C3/D3；严格拒绝而未清洗模型字符串强行执行。关闭思考使temperature生效，但没有消除模型协议错误。
- 旧16题A10/B14、185题A177/B177，pass向量与SQL/rows/status保持M1-B1一致；业务语义22题9/22、22/22、22/22，正向0/12/12。旧f01/f02及8题失败保持原结果。
- 扩大选定回归：412 passed、3 failed、3 warnings。三个失败在起点5a5f14f快照原样复现：显示别名物理结果核验、reset后的上下文模式预期、追问绕开模型的测试预期。原始日志与起点复现均保留，不称全绿。
- HTTP/SSE接入使用真实TestClient及确定性fake planner验证；付费真实模型通过同一个OmniAgent Python入口执行，不声称已经部署线上DeepSeek服务。
- safe-09仍是P0历史安全契约问题，本轮未改安全逻辑。建议独立在完整原始问题的统一入口拒绝混合写入/绕过意图，并用“删除查询筛选条件”等合法范围编辑反例做专门回归；不混入记忆成绩。

| 条件 | 当前证据与结论 |
