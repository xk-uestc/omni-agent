# 问数与文档页面的共享会话

## 改动与效果

原问数页使用 `ict8_lattice_session`，文档页使用 `ict8.omni-session`，同一浏览器页面跳转会进入不同会话。本轮新增 `frontend/conversation-session.js`，两页共用当前会话，并提供会话选择列表。

- 原来两个会话均保留，不合并后端历史。首次访问优先当前页面旧会话，之后导航沿用已选择的共享会话。
- 新建会话保留旧会话，可切回后输入“查看待补问题”恢复原任务。
- 会话按 API origin 与路径隔离，避免把不同服务的会话混用。
- 切换时取消当前前端请求，清除可见旧内容；迟到响应不能更新新会话，即使随后切回同一编号也不会误更新。
- 文档页查询、澄清和任务恢复统一通过单请求控制器；旧选项在发送时锁定。
- 页面从浏览器历史缓存恢复时重新读取当前会话。
- 存储不可读写时降级到当前页面内存并提示；达到列表容量时明确拒绝新建，不静默删除旧记录。

真实 8030 服务验证使用生产 JS 会话控制器与共享模拟存储：8/8 HTTP 对话检查、11/11 身份/资源检查通过。问数页待补问题由文档入口补完；旧文档会话由问数入口恢复。两次月度查询分别与独立 SQLite SUM/COUNT 参考逐行一致；新会话无旧任务，原会话已完成任务仍关闭。5个页面/脚本 HTTP 内容哈希均与本地一致，验收前后源码哈希稳定。

- 脚本：`tools/verify_shared_conversation_http.js`

服务模型沿用用户授权 gpt-6-luna 配置；未读取或输出凭据。本轮未修改后端，不重复全量后端测试。

## 限制

这是生产会话逻辑加真实 HTTP 验收，不是浏览器实际点击验收，也不是官方盲测成绩。共享以同源同标签页 sessionStorage 为范围，不承诺跨标签页、关闭浏览器或跨设备同步。存储不可用时不承诺跨页面保留。

切回旧会话不会重绘全部历史回答，后端上下文和可用待补任务保留仍受各自期限限制。前端 abort 不撤销服务器已开始执行的请求。比较/文档/跨源长期待补、任意多对象指代、复杂文档与通用多轮泛化仍未完成，不能据此标记整体赛题完成。
