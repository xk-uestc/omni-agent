# 扫描表格层级与方向选择

本轮继续完善真实文档鲁棒性。能力为可追溯的表格结构预览，不是已核验业务数据，不代表官方基准或目标全面完成。

## 两个独立Agent

`ScannedTableStructureAgent`以用户明确指定的表格序号及0～5行表头整理矩形网格。合并标题组成每列标题路径；纵向合并标题不重复；数据保留原行列、合并范围、空白、OCR观察及原图位置。跨表头/数据边界的合并、重叠、覆盖断裂、锚点不一致拒绝。重复或缺失标题保持待核对。0行表示没有表头，不生成业务字段名，也不吞掉第一条数据。

`ScannedGridSelectionAgent`先比较方向依据，再比较单元格文字覆盖率、数量与置信度。可观测的正向文字优先；基于前轮可靠方向证据完成校正的候选次之；方向不明或仍侧转的候选不能仅凭识别框多而替代正确方向。

存在完整轴向规则网格、文字方向为90/180/270度且OCR额外倾斜估计不超过3度时，使用对应直角校正，防止文字框约2度噪声破坏表格线。没有完整网格或明显真实倾斜时保留原方向/倾斜处理。此选择仍是图像与文字证据驱动的有界规则，不是通用页面语义模型。

## 真实缺陷与证据

第一次HTTP实测：无表头公开页和原向夹具通过，90度夹具失败，未校正候选错误输出3行4列。失败报告保留`runtime/scanned-structure-http-170f7ffa386f49258a6a4795ba6d4a36.json`。

优先方向后仍失败：原图90度，但OCR预测附带1.981度倾斜，校正后的网格消失；系统返回不可整理而非继续误解释。报告`runtime/scanned-structure-http-a53676c650a344628e02409906d3185b.json`。

最终直角网格修复后HTTP3/3通过，报告`runtime/scanned-structure-http-24bd7b9c93d24e86a9ec5487fc5b1667.json`，受检源码hash稳定：

- OHR公开预算PDF第一页的实际渲染图，人工查看确认没有表头，指定0行后保留11行×2列及首条Personnel/$47,000。这里只核对结构、首行保留与来源，不评分全页OCR文本准确率。
- 受控打印夹具真实RapidOCR：两级表头Region、Sales/2024、Sales/2025及East/West四个数值全部对应。
- 同一夹具真实90度旋转输入，恢复相同4行×3列与表头/数据。两个夹具不是公开原件或官方盲测。
- 公开页22个数据锚点、两夹具各6个数据锚点和5个标题引用，原图框全部eligible且source SHA匹配对应输入，0个位置失配。

早期默认1行的公开页观察报告保留`runtime/scanned-structure-public-2ac0a10a80354cc89bfc8f1e6d41236b.json`；这是错误表头选择的开发观察，不能当成功语义证据。原页可视检查促成0行支持。

## 接口和网页

`POST /api/v1/documents/ocr`增加可选`table_header_rows`和0起始`table_index`，仅显式选行后返回`metadata.table_structure`。现有请求默认不变。网页扫描区增加表头行数与1起始表格序号输入、层级标题和带真实rowspan/colspan的数据预览；使用文本DOM输出，不将OCR文本作为HTML执行。

首页、知识页面均HTTP200，知识页脚本缓存更新为`20261005-table-structure-1`。服务仍配置gpt-6-luna，当前OCR/结构测试使用本地RapidOCR，无新增模型API调用。

## 验收和限制

- 方向/OCR/坐标/网格/结构/透视相关129项通过，1既有弃用告警。
- API权限和PDF视觉接口另32项通过，与前组不同测试文件。
- 前端现有上下文/请求/SVG41项通过，knowledge.js语法通过；没有真实浏览器点击验收，也没有全项目重跑。
- 公开页存在Office Supplies的`$2.000`与原图`$2,000`不一致等问题，保留OCR原文。金额不能自动用于已核验计算。
- 标题行仍由用户指定；自动多级表头推断、跨页表格、任意无框表格、数值独立核验和结构化入库尚未完成。
- 本轮未把表头选行接入PDF逐页预览，只有图片OCR接口与扫描图片工作台；PDF原图坐标既有链路保持。

整体目标保持未完成，不能从三个曝光样例宣称全部真实文档和复杂对话已达顶级水平。
