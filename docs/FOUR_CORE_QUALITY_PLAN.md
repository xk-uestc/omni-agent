# 四项核心能力的持续质量目标

目标保持为：围绕赛题结构化与非结构化部分，四项能力都达到有可靠泛化证据的高质量效果。局部补丁、已曝光开发题通过或一次小样本提升不构成总体完成。

## 选定范围与验收

| 核心要求 | 对应赛题 | 必须验证的行为 | 当前证据不足 |
|---|---|---|---|
| 复杂 NL2SQL | 单/多表、聚合、嵌套、Schema Linking、要素及歧义识别 | 跨领域新 Schema；准确的过滤/时间/连接粒度/投影/排序/单位；完整结果与截断分开；模型不能高置信任选歧义来源 | Chinook 等小型开发集不能证明未知业务复杂查询达标；19119组结果仍未完整分页 |
| 多文档与多模态 RAG | 异构来源定位、文本/表格/图表/公式/版面、原件溯源 | 新文档和新问题隔离；完整答案、全部条件、引用支持和计算方向；拒答、摘录、实质回答分别计数 | 已曝光原12题提高仍不足；新8 query仅1个精确匹配；扫描表格、公式、多部分问题仍有缺口 |
| 跨源多跳推理 | 至少5类跨源工作流、明确依赖、结构化与非结构化联动 | 数据库→文档、文档→数据库、公式计算、三源预测、阈值/版本比较；真实工具依赖；所有用户约束与源版本保留 | 原44题未在最新代码上完整复测；仍需新领域与组合流程，而非拼接不同版本定向通过数 |
| 连续对话与通用适配 | 连续5轮以上、澄清补全、主题切换、异常恢复 | 指标/地区/时间替换、未知条件拒绝、失败后的状态、完整新问题独立执行、文档版本变化及实际重启 | 历史5轮开发回放不代表任意业务；需有新 Schema/新工作流的严格整段验收 |

官方赛题对复杂 NL2SQL、多文档/多模态 RAG 的满档准确率阈值为90%。这只是必要的效果目标；“业界领先”还需公开方法和统一条件下的比较，不能用局部自建题的高通过率替代。

## 评测纪律

- 使用 `gpt-6-luna`、medium；真实 API 与规则/stub 测试分开。
- 在实现者查看测试问题、答案和结果前冻结数据、选择方法及哈希。按文档、Schema和问题族区分曝光程度，不以同文档新问题冒充新文档盲测。
- 原 PDF/数据库是系统输入；GT、答案和 reference SQL 只在程序返回后进入评分，不能作为检索原件或提示词。
- 每轮固定分母，保留空结果、截断、错误澄清、拒答、API失败和退步；页命中不等于答案正确，答案字面一致不自动证明完整语义。
- 基线与新版用相同输入、模型协议和数据快照；保存每次实际输出、源码起止SHA、调用和token统计。一轮一次的模型波动不宣称统计显著。
- 新集首测只提供小样本证据；查看失败后再改实现，该集转为开发集，必须继续扩充真正独立的新数据，不重新命名为盲测。
- 只有四项要求都得到匹配其范围的实测证据后，才可宣布长期目标完成。当前目标保持进行中。

## 本轮执行

1. 修复实际 SQLite 带空格/连字符/点号/引号的物理名称适配，基于真实 Schema 精确白名单和编译转义；保留逻辑指标 ID 约束。
2. 歧义指标/维度不能被模型置信度绕过，明确来源仍可查询。
3. 图表百分比保存精确 Fraction、基期/方向/分母与明确舍入政策；保留完整问题独立复核及原件重放。
4. 删除 SQL 追问范围校验后的重写旁路；补缺指标短回复；校验失败的依赖追问必须澄清，不能退化成全量统计。
5. 新冻结7份原 PDF、18题、75页，六类各3题，和既有文件名/原件SHA零重叠；新 Northwind 13表、16个自编跨Schema问题。前者是官方数据小样本，后者是公开示例库开发评测，均不等于完整官方榜单。

## 公开方法参考与适用边界

2026-10-02读取以下 arXiv 官方页面标题与摘要，借鉴方法思想，不复用其论文成绩为本系统成绩：

- [DIN-SQL](https://arxiv.org/abs/2304.11015)：分解 Schema/查询子任务与错误校正；对应本系统类型化计划、服务器语义校验和有界修复。其论文实验不是本系统的效果证明。
- [Self-RAG](https://arxiv.org/abs/2310.11511)：按需检索并评判支持性；本系统的独立复核不等于论文训练得到的反思 token 模型。
- [CRAG](https://arxiv.org/abs/2401.15884)：评估检索质量、分解再重组证据。后续重点是低覆盖时补充检索，避免以固定top-k或单次不足证据判定结束；该方向尚未因此文档而自动实现。

后续还需扩大官方新文档评测、检查检索与完整上下文覆盖的失配、跨 Schema 的复杂算子和五轮新工作流。每项进展以代码和独立运行报告为准。
