## 已修复的实际错误

- 完整新 SQL 问题不再因为“那/呢”继承旧文档与公式；真正省略追问仍继承已验证范围。
- 预读正确公式不能授权实际使用另一公式。最终计算必须消费真实公式任务，并保持标签、来源、SHA、表达式和相关 SQL 祖先一致；多个明确目标不能遗漏一个。
- `总费用/记录数` 的 SUM 与 COUNT 参数交换不能因为公式与 SQL 都正确而通过。逐参数从业务目录、物理 Schema 或来源文档的明确参数声明核验实际聚合槽，展示标签、数值相等、单位相同都不能单独授权。
- SQL 第一名到文档检索的地区引用必须与原问题独立规则取数的完整物理结果一致；自行替换 SQL、rows 和 hash 不能构成证明。并列赢家不能只检索第一条。
- 显式条件及单位标题持续约束同段各事实，空段或明确章节边界才重置；超过八个声明后整个剩余范围拒绝，不通过截取后缀授权。

## 未知公式参数的明确声明

泛称“基准金额”不能自动当作销售额。原文档可明确写：

```text
预测总额 = 基准金额 * 1.1
参数绑定：基准金额 = SUM(sales_orders.sales_amount)
```

绑定声明必须完整匹配支持的物理聚合语法；字段必须真实存在；重复声明不得冲突，已知业务目录定义不能被反向覆盖。服务器保存来源 SHA、locator 和规范化提取文本中的完整声明。它是来源中的业务数据声明，不是执行文档命令。
