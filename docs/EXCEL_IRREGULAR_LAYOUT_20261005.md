## 实际能力

| 类型 | 处理方式 |
|---|---|
| 标题、脚注、备注 | 保留原文字与坐标，和记录分开 |
| 两层／三层合并表头 | 按几何锚点展开完整字段路径，区分重复字段 |
| 合并数据维度 | 空覆盖格保留原值为空，文字维度查询可引用锚点，并返回条件来源坐标 |
| 合并金额 | 仅原锚点存数值；覆盖格不可当另一个数值输入 |
| 上下、并排、无空行分段 | 按明确区域、空白间隔或不同表头分块，保留每块范围 |
| 空行、空列与偏移 | 不生成空白记录；物理列号和原行号保留 |
| 无表头、全字符串表 | 未知结构保留首行，使用物理列名，允许指定0层表头 |
| 重复、空白字段 | 列名唯一化；未知重复数据行不当表头删除 |
| 百分比、日期、金额、编号 | 保留原类型、原值、数字格式；支持有限格式展示及纯零掩码编号 |
| 单独单位行 | 和记录分开，单位写入列和单元格元数据，并传给取值工具 |
| 公式与缓存 | 不计算公式；有缓存也标未核验，不能当计算输入 |
| 小计／合计 | 保留原行并标记summary，不自动作为明细求和 |
| 空、零、false、错误 | 不混同；数值和布尔筛选区别处理，错误值不能作为计算输入 |
| 隐藏内容 | 保持原文件完整，默认不进入检索，不能通过指定区域读取隐藏表 |
| 极远单元格／格式膨胀 | 使用稀疏单元格，不扫描整张巨大包围矩形 |
| 多工作表、空表、Excel正式Table | 保留工作表来源，优先明确Table定义；空表不伪造数据 |
| 宽表、长文本 | 分片仍带完整单元格元数据；知识库不再二次重分片丢失sheet/row；取值按物理坐标去重 |

每份表的所有可见原始非空单元格都在发出记录或原文上下文时登记，末尾核对无遗漏；表头和上下文额外保存 `source_cells`。已存在的来源文件哈希验证继续生效。SHA-256用于来源完整性，不宣称内容正确性。

## 结构确认接口与页面

`/api/v1/documents/chunks-preview` 和 `/api/v1/knowledge/ingest` 增加可选字段：

```json
{"excel_tables":[{"sheet_name":"数据","range":"D6:F10","header_rows":2}]}
```

最多64块、表头0至8层；工作表不存在、区域越界／反向／重叠、空区域、隐藏表头均拒绝。用户定义优先，区域外可见单元格仍继续自动读取与保留。仅适用于xlsx。

知识页新增独立Excel预览：每块展示字段、原行号和最多12行／20列（明确说明截断，后端保留完整读取结果）；点击单元格高亮并查看原值、格式、锚点及坐标。可重新设置区域与表头层数后加入资料库，确认设置随本次入库保存；不修改原件。不确定时可重新上传同文件确认。

## 限制与未完成

不可能通过有限样本证明“任意Excel完美读取”。无明确分隔的未知业务表、多个纯文本表头／数据混排、图形或嵌入截图、数据透视表的业务意义、外部链接和复杂自定义显示格式仍可能要求指定区域与表头。自动表头判断有启发式词表，明确用户设置是纠正通道，不替代任意语义识别。

仅支持xlsx，旧xls、xlsb、加密文件需先转换；宏和外部链接不执行。公式未实现可信重算（当前没有可用LibreOffice），不把故意错误缓存999当60。合并数值、小计总计、跨表汇总不自动推断统计语义。空白、错误、缺失数据不会凭空补齐。资源仍有限：20MiB上传、解包限制、默认50万单元格／合并／单表展开预算及chunk上限；合并展开在openpyxl分配前检查，超限明确拒绝，不声称无限大表支持。

已有资料库不会静默重写，旧已导入Excel需重新上传才能采用新版结构。当前开发测试未证明自然语言问答每个场景都正确，已验证的是读取、单元格来源、预览、保存和明确条件的工具取值。未混合提交协作者脏工作树，也未宣称已推送GitHub。
