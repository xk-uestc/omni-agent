# 多轮历史引用 Agent

## 实现

`backend/history_reference.py` 将引用解析与来源选择独立成 `ConversationReferenceAgent`，输出不可变请求/选择对象。它不执行SQL、不调用模型、不确认来源成功；选中记录后仍由 `sql_history_scope` 校验执行记录摘要、数据源版本及条件合并。

支持：

- 原有“回到上一次SQL查询，那华南呢”。
- “回到倒数第二次SQL查询，那华南呢”；阿拉伯/中文数字，倒数位置只计算保留的SQL尝试，不计算文档话题。
- “回到倒数第二次成功的SQL查询，那华南呢”；只有用户明确说成功才筛选成功记录，不悄悄跳过失败。
- “回到SQL查询‘完整问题’，那华南呢”需使用中文双引号、ASCII双引号或「」；精确匹配原问题或实际完整问题，重复匹配必须澄清。

历史窗口外、重复匹配、未成功/来源改变、未支持的正序编号、嵌套引用都不能退化为独立SQL或改用最近一次结果。不存在的引用在意图模型前澄清。核验通过的明确SQL引用由服务器固定SQL路由，仍执行正常的SQL规划与执行验证；保留原有模型审查短句条件修改能力。引用元数据展示实际来源问题和历史窗口位置。

## 实测

“2025年华东销售额→2024年华北订单数→文档插话→回到倒数第二次SQL查询，那华南呢”实际执行结果为销售额22992.0，与独立SQLite时间/地区过滤SUM一致；没有错误继承最新的2024年/订单数。另有完整问题引用、重复记录拒绝、数据源变化拒绝、空会话/窗口淘汰、持久化重建及会话隔离反例。

- 首组新测试104通过/3失败是测试误用二维行数组及直接Agent并不存在的顶层answer字段；修正为实际字典rows和result.clarification后107通过，不声称发现业务算法故障。
- 相关较宽回归213通过、1既有弃用警告；随后固定明确引用路由的集成/Omni回归59通过。
- 最终恢复原有模型短句验证入口并拒绝嵌套引用后，引用Agent/SQL历史/集成专项96通过。以上套件有重叠，不累加为总测试数。
- 实际gpt-6-luna模型服务HTTP6/6轮通过：`runtime/history-reference-http-7814e43855d345a7b4892a081a30fb98.json`。

## 剩余目标

本轮开发数据并非官方准确率。历史仍是有限保留窗口，未支持会话开头正序编号、模糊语义引用、比较任意两项来源、多对象同时编辑或分布式会话锁。真实低质量文档的多行语义/多区块/透视/跨页、数值核验与结构化入库仍需完善。全项目回归和浏览器点击未完成，整体目标保持未完成。
