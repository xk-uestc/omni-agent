# 多轮比较中的查询条件修改

## Agent 流程

ConversationComparisonEditAgent 负责识别修改对象与条件；SQL历史解析器核验原执行记录与未修改条件；正常 Omni/SQL 链路重新执行所选查询；ConversationComparisonAgent 验证新旧快照并对齐计算。

没有修改对象的短追问不会交给模型猜测。“那华北呢”先询问基准或比较查询，选择后保留原年份、指标和其他条件。完整新问题、文档话题切换保持独立，不强行塞进比较流程。

## 已支持的复杂情况

- 最近两项结果比较后，修改基准或比较查询。
- 基准切换后，按当前角色选择修改对象，不误用最初下标。
- 连续两轮修改地区、年份，未选一侧保持原结果。
- 含明确角色的完整问题替换，例如“把比较查询改成2024年华北销售额”。完整问题不重新插入旧地区或旧年份。
- 来源版本变化在执行修改前被拒绝。
- 未知排除条件、无法证明的改写、执行不完整时保留原比较来源；之后可以继续比较原两项。
- SQLite会话重建、跨会话隔离、澄清后选择对象，以及正常文档话题切换。

首页来源区可以选择“修改基准查询/修改比较查询”，会在输入框填入明确对象。条件实际执行后展示原问题→新问题，并说明本轮执行了哪一项，避免把修改查询误称为纯快照计算。
