# 连续对话：来源选择、跨表参数修改与长期文档返回

本轮在成功查询原子修改的基础上，补充原先缺少的三个方向。能力有明确范围，不能把有限开发测试称作任意指代均正确或赛事官方成绩。

## 交互行为

1. “它的退货期限是多少”“之前那份文档……”存在多个成功来源时，返回带编号的具体问题／文档候选；选择后继续原本要问的问题。越界、不是本次提供的编号、来源过期或其他会话编号都不能触发查询。单一来源且最近一轮有效时直接继续；新问题失败后，裸代词不得静默跳过失败轮借用更早成功结果，即使只有一项也先要求确认。“前者／后者”只有明确两项候选时可用，第三项出现后重新询问。完整的新主题如“这个月销售额”不会被当作来源代词。
2. `查询文档“甲产品说明”：保修期限是多少`限定到唯一标题的原件；`同样的问题换成文档“乙产品说明”`只沿用问题，不沿用答案；`回到文档查询编号q_…，退货期限是多少`可越过短对话窗口重新检索原文。文档问题在页面提供“继续问这份文档”入口。
3. 复杂跨表成功查询可明确修改`customers.region`、`payments.channel`等现有等值筛选，及唯一绑定的年度范围。例如`customers.region改成华南，payments.channel改成线下，时间改成2024年`。最多四项修改，原SQL字节不变，改动仅发生在已绑定的WHERE参数；重新读取真实数据库，不调用模型重新生成JOIN／CTE／聚合表达式。单独“时间改成2024年”也可使用此通道。

## 记录与执行约束

- 新`ConversationSourceStore`与短规划历史分开，默认每会话最多64条、最长24小时、最多512个会话；同会话清除会一起清除长期来源。来源记录支持SQLite持久化；这不是永久无限记忆。
- 文档记录保存问题、来源ID和原件SHA-256。选中、读取前和读取后重新核验版本，发布前核对每条引用。旧版本更新、原件损坏、读取过程中换版本时都丢弃本次答案。来源一致性记录的SHA-256用于检查服务器记录完整性，不宣称密码学签名。
- SQL修改在一致只读事务中核验原问题、SQL、参数、来源版本与记录摘要。SQLGlot把占位符按实际文本顺序绑定，而不是用AST遍历顺序推测参数位置；CTE、关联、投影、NULL表达式、分组、HAVING、子查询、排序及其余参数保持原样。
- 仅处理WHERE合取项中的唯一物理字段等值筛选；字段实际新值需在当前库存在，原文本与旧参数须能唯一绑定。时间限唯一年度半开区间，支持原生日期比较及双方一致的无修饰`JULIANDAY`转换。OR分支、JOIN键、HAVING、函数修改、多个冲突日期、指标替换和增删关联均不能经此通道编辑。
- 查询沿用现有只读执行器的行数、步骤和时间预算。完整结果文件交付不经这个新通道；到达预览上限标记partial_rows，不把其保存为新的成功上下文。
- 一项无法核验则整条修改不执行，不写入伪成功历史；非法来源也不能静默回退到另一份文档或无筛选SQL。
